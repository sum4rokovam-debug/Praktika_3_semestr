# Отчёт: поиск нетипичного поведения заявок на закупку

## 1. Инструменты и воспроизводимые шаги

- Python 3 + pandas. Скрипт `analyze.py` читает журнал и целиком воспроизводит `anomalies.csv`. Запуск: положить `students.csv` рядом со скриптом, `pip install pandas numpy`, затем `python3 analyze.py students.csv anomalies.csv`.
- Шаги: (1) загрузка, перевод времени в UTC+3, сортировка по `EventIndex` внутри процесса; (2) проверка качества данных; (3) сборка «маршрута» каждой заявки (последовательность этапов и результатов); (4) расчёт длительности каждого задания (закрытие минус создание по `TaskId`), календарной и рабочей (пн–пт, 09:00–18:00); (5) сравнение с нормой по этапу и типу заявки; (6) формирование списка с объяснениями.

## 2. Что считаем обычным поведением

В журнале 1000 заявок, 12 162 события, одна версия шаблона. Дубликатов `EventId` нет, `EventIndex` без пропусков, время внутри процесса не убывает, все события в рабочие часы будних дней.

Типичные маршруты (990 завершены, 10 открыты):
- standard/urgent: Проверка → Руководитель → Бюджет → Исполнение (496 + 133 заявки);
- contract: то же + Юрист между бюджетом и исполнением (150);
- отказ руководителя (45 заявок), возврат на доработку с одним циклом (около 119 заявок).

Роли по этапам однозначны: проверка — specialist, руководитель — manager, бюджет — finance, юрист — legal, исполнение — procurement, доработка — requester.

Нормальные длительности (рабочие часы, медиана): проверка ~0,4 ч (urgent ~0,14), руководитель ~2 ч (urgent ~0,7), бюджет ~2,6 ч (urgent ~0,9), юрист ~3,7 ч, исполнение ~5 ч (urgent ~1,8). Паузы между этапами ~0,25 ч, без выбросов. Срочные заявки заметно быстрее — поэтому сравнение везде идёт внутри типа заявки.

## 3. Критерии поиска

Нарушения процесса (по маршруту и ролям): пропуск этапа «Руководитель»; исполнение до бюджета (и юриста); повторная проверка без возврата; согласование ролью, не равной manager; события после среза.
Необычное, но не обязательно нарушение (ручная проверка): внеплановые проверки аудитора; 5–8 возвратов подряд.
Время: незакрытые задания старше нормы в разы (а не просто «открытые»); задания, закрытые за секунды; проверки в десятки раз дольше медианы.

Допустимое и НЕ включённое: один возврат на доработку, отказ руководителя, нормальные ночные/выходные паузы, 2 открытые заявки на этапе исполнения, созданные 30 июня (незавершённость сама не аномалия), длинные «хвосты» исполнения и юриста (до 17,5 ч — укладываются в вариацию).

## 5. Ложные срабатывания, ограничения, ручная проверка

- Внеплановые проверки аудитора (8 заявок): по редкости нельзя понять, оправданы ли они; сумма и тип заявки их не объясняют. Нужна ручная проверка.
- 8 проверок ровно по 8,0 раб. ч: могут быть нормальной задержкой одного рабочего дня — наименее уверенный тип.
- Верхний «хвост» бюджета (8,75 ч — 3 случая), юриста (14 ч) и исполнения (17,5 ч) ровно на границе вариации; не включены.
- События после среза (10 процессов, 1 июля): возможно, это сбой выгрузки, а не поведение сотрудников.
- Единственный инициатор во всех 1000 заявках (UserId одинаков) — поэтому «самосогласование» проверяется только по этому пользователю; индивидуальные профили исполнителей не анализировались глубоко.
- Нет данных о причинах, комментариев, праздников и обеда — длительности приблизительны. Пороги выбраны по распределению данных и могут быть пересмотрены.
